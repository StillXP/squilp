# Contributing to Squilp

Squilp is early. The full contribution process (Proposal and Submission forms on the docs site that create GitHub issues) arrives with the docs site; see decision 0011 and the Contribution section of [`docs/plan.md`](docs/plan.md).

Until then:

1. **Open an issue first** describing the problem, real use cases, and why nothing in Squilp already covers it.
2. **Wait for the issue to be accepted** before building.
3. **Meet the submission requirements** in the plan: tokens only, built from existing components, WCAG 2.2 AA, Figma and code in step, docs page, tests, component metadata and a changeset.
4. **Use Conventional Commits** for commit messages.
